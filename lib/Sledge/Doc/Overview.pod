=head1 NAME

Sledge::Doc::Overview - Overview of the Sledge framework

=head1 DESCRIPTION

This document briefly explains the architecture of the Sledge framework.


=head1 LIFELINE

An HTTP request that arrives at the web server is processed in the
following order. (This is an outline; some parts differ from the
implementation.)

=over 4

=item *

mod_perl (Apache::Registry) or a CGI script acts as the trigger and starts the application (Pages)

=item *

Load plugins (optional)

=item *

Create the Sledge::Pages object

=item *

Initialize the application Config

=item *

Process the HTTP request parameters

=item *

Initialize each Factory object

=item *

Get / issue the session ID

=item *

Restore the session from storage

=item *

Authorize access to the page

=item *

Filter character encodings

=item *

Load the template engine

=item *

Dispatch to the application class

=item *

Run the template engine

=item *

Generate sticky forms (as needed)

=item *

Filter the output content

=item *

Return the response to the server

=back
