=head1 NAME

Sledge::Doc::FAQ - Sledge FAQ

=head1 DESCRIPTION

Sledge frequently asked questions and answers

=head1 QUESTIONS

=head2 INSTALL

=over 4

=item Q.

The CPAN shell tries to install perl 5.6.1.

=item A.

Upgrade the CPAN module to the latest version.

  cpan> look CPAN
  # perl Makefile.PL ; make install
  # exit
  cpan> reload cpan

=item Q.

Can it be used in a CGI environment?

=item A.

Yes, since 0.03. In your Pages base class, do

  use Sledge::Pages::Compat;

It automatically inherits from one or the other depending on the
environment variables.

=back

=head2 SLEDGE FRAMEWORK

=over 4

=item Q.

Can multiple Sledge projects be used on one server?

=item A.

Yes.

Even under mod_perl, it works without problems as long as the project
names are different. The CGI version has no particular problems either.

=item Q.

I want to redirect between HTTP and HTTPS.

=item A.

If you add a scheme (http || https) as the second argument of the
redirect() method, it redirects to that scheme. If you need things like
path conversion, override redirect() or current_url().

=item Q. I want to stop FillInForm

=item A.

Set false with the fillin_form() accessor.

By default, fillin_form is enabled when $r->method eq 'POST'. To disable
it, explicitly call $self->fillin_form(undef);. It is OK to run it
anywhere in dispatch_*.

If you want to stop it for all dispatch_* methods in the class that uses
it, do

  sub fillin_form { undef }

=item Q.

There are several forms in the page, but I want FillInForm to fill in
only one of them.

=item A.

Set it on the attributes of the fillin_form() instance.

The fillin_form attribute holds an instance of Sledge::FillInForm.

  $self->fillin_form->target('foo');

If you call this, only the FORM E<lt>FORM name="foo"E<gt> is targeted
by Fillin.

However, if you run the above on GET, you get an error like this:

  Can't call method "target" on an undefined value at ...

This is because by default fillin is not done for GET. To keep this
statement from becoming a runtime error on GET, either call
load_fillin_form() first to put things in the same state as POST, or do

  $self->fillin_form->target('main') if defined $self->fillin_form;

=item Q.

I want to add a foject to pass to FillInForm.

=item A.

You can add one with the fillin_form->add_fobjet() method.

  $self->fillin_form->add_fobject($fobject);

As above, be careful that this does not cause an error on GET.

=item Q.

I want to enable fillin_form on GET.

=item A.

If you explicitly call load_fillin_form(), you get the same state as
POST.

  $self->load_fillin_form();

=item Q.

Is it OK to make a .cgi that has no corresponding template file?

=item A.

No problem.

However, you must run load_template() or redirect() before dispatch()
finishes. Otherwise an exception occurs in the final tmpl->output.

=item Q.

I do not need session management

=item A.

Override construct_session.

  package YourProject::Pages;
  sub construct_session { }

=item Q.

How do I handle uploaded files?

=item A.

In both the mod_perl and CGI environments, you can get an Upload object
with $self->r->upload('uploadname'), and get a handle from it with the
fh method.

  my $upload = $self->r->upload('uploadfile');
  $upload->link("/path/to/savefile");
  my $fh = $upload->fh;
  while (<$fh>) { do_something($fh); }

For details see perldoc Apache::Request and perldoc CGI.

=item Q.

How do I write a program that lets the user download a file?

=item A.

You must not output a template, and you must output the HTTP headers
yourself. Below is a sample that lets the user download the PDF data
contained in $data.

  sub dispatch_download {
      my $self = shift;
      my $data = $self->fetch_pdf_data;
      my $filename= 'test.pdf';
      $self->r->content_type("application/download; name=$filename");
      $self->r->header_out('Content-Disposition' => "attachment; filename=$filename");
      $self->r->send_http_header;
      print $data;
      $self->finished(1);
  }

Call finished() to skip the post-processing, that is, the header and
template output.

=item Q.

The MySQL sessions table keeps growing. Is that expected?

=item A.

Yes, it is. Add a timestamp column and clean up periodically with an SQL
statement like the following.

  DELETE FROM sessions WHERE timestamp < SUBDATE(NOW(), INTERVAL 2 HOUR)

=item Q.

I want to delete session data when dispatch_foo finishes

=item A.

Add it to the AFTER_DISPATCH hook.

  $self->register_hook(AFTER_DISPATCH => sub {
      my $self = shift;
      $self->session->remove('foo');
  });

See Sledge::Doc::Hooks for details.

=item Q.

I want to use my own cookies

=item A.

To use persistent cookies that sessions cannot handle, you can set them
with header_out.

  use CGI::Cookie;
  my $cookie = CGI::Cookie->new({ ... });
  $self->r->header_out('Set-Cookie' => $cookie);

=item Q.

How do I load a template from another directory?

=item A.

You may want to load a common error page, $TMPL_PATH/error.html, when
an error occurs. You can swap the template contents with the
load_template() method, but with something like

  $self->load_template('../error');

you have to be aware of the current directory. If you write it starting
from /, it is loaded as a virtual path.

  sub display_error {
      my $self = shift;
      $self->load_template('/error');
  }

In this case, error.html directly under the Config TMPL_PATH is loaded.

=item Q.

I want to handle GET and POST differently.

=item A.

For a POST access, post_dispatch_foo is run first.

=item Q.

I do not want dispatch_foo to run after post_dispatch_foo.

=item A.

Call the C<output_content> method. C<finished(1)> is not needed.

  sub post_dispatch_foo {
      my $self = shift;
      $self->output_content;
  }

=item Q.

For some reason I cannot use the POST method, but I still want to branch
the processing.

=item A.

Override the is_post_request method.

  sub is_post_request {
      my $self = shift;
      return $self->r->param('.post');
  }

In this case, foo.cgi?.post=1 is treated as the POST method.


=item Q.

I want to pass a hash to FillinForm instead of an object that implements
param()

=item A.

Do

  $self->fillin_form->fdat(\%fdat);

Note that when fdat is set, the object is ignored.

=back

=head2 TROUBLE SHOOTING

=over 4

=item Q.

I get an error like this.

  Can't use string ("Foo::Config") as a HASH ref while "strict refs"
  in use at /usr/local/lib/perl5/site_perl/5.005/Sledge/Config.pm line 40.

=item A.

Check that the Class::Singleton module is installed. If it is, the way
you call the Foo::Config module is wrong.

=item Q.

I get an error like this.

  Can't call method "param" on an undefined value at
  /usr/local/apache/site_perl/HelloWorld/Pages/Index.pm line 6.

=item A.

If the line in question is

  $self->tmpl->param()

then the template file could not be loaded. Check that the template path
and file name are correct.

=item Q.

Changes to the Config are not reflected. I am using Apache::StatINC.

=item A.

Class::Singleton is the cause. If you inherit from Apache::Singleton
instead of Class::Singleton, the instance is cleared on every request.
Performance drops slightly, but the impact should be negligible.

=item Q.

FORM values such as hidden fields set in the template get overwritten by
the POSTed values.

=item A.

See the fillin_form items above.

=back
