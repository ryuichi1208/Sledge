=head1 NAME

Sledge::Doc::Tutorial - How to use the Sledge framework

=head1 DESCRIPTION

A tutorial for Sledge beginners

=head1 FIRST STEP

Installation and project setup are explained in Sledge::Doc::Install;
please refer to it.

Here we create the HelloWorld project and write the project base
directory as /usr/local/hw. In practice, substitute your own project
directory.

A typical directory layout looks like this:

  /usr/local/hw/lib		Perl modules
  /usr/local/hw/htdocs		Docroot, where the .cgi triggers live
  /usr/local/hw/template	Template files

=head2 PERL MODULES

Move the HelloWorld directory created by the setup script to
/usr/local/hw/lib.

  % mv HelloWorld /usr/local/hw/lib

Configure things so that /usr/local/hw/lib is included in @INC (the
include path for Perl modules).

  1) setenv PERL5LIB=/usr/local/hw/lib
  2) use lib
  3) symlink from /usr/local/lib/perl5/lib

are possible ways. 1) is the easiest. To set it in httpd.conf, use

  SetEnv PERL5LIB /usr/local/hw/lib
  PerlSetEnv PERL5LIB /usr/local/hw/lib

The first line is for the CGI environment and the second for the
mod_perl environment.

=head2 CGI FILES

In the Sledge framework, a .cgi is started from Apache::Registry and
acts as the trigger for a Pages class. Write
/usr/local/hw/htdocs/index.cgi as follows.

  #!/usr/local/bin/perl
  use strict;
  use HelloWorld::Pages::Index;

  HelloWorld::Pages::Index->new->dispatch('index');

HelloWorld::Pages acts as the Pages base class of the project. There is
no problem writing dispatch_ methods in this class, but we recommend
putting the default settings in this class and implementing the actual
dispatch methods in subclasses.

Here we write the corresponding method in HelloWorld::Pages::Index,
creating a method named dispatch_index.

  package HelloWorld::Pages::Index;
  use base qw(HelloWorld::Pages);

  sub dispatch_index {
      my $self = shift;
      $self->tmpl->param(cur_date => scalar localtime);
  }

Here the current time is assigned to the template variable cur_date.

=head2 TEMPLATE

Create the corresponding template file. Write the HTML in the file
/usr/local/hw/template/index.html.

  <HTML>
  <BODY>
  Hello World! Current datetime is [% cur_date | html %]
  </BODY>
  </HTML>

Now, when you hit index.cgi from a browser, this HTML should be
displayed.

=head1 CONFIGURATION

This section shows how to change various settings.

=head2 TEMPLATE DIRECTORY

The directory that holds templates is set as the class data
tmpl_dirname. To change the directory, create a new Pages class and set
the class data.

   package YourProj::Pages::Foo;
   use base qw(YourProj::Pages);

   __PACKAGE__->tmpl_dirname('foo');

With this, $Config{TMPL_PATH}/foo/pagename.html is what gets loaded.
The page name is the argument to dispatch(). That is, for

  YourProj::Pages::Foo->new->dispatch('bar');

$Config{TMPL_PATH}/foo/bar.html is loaded.

=head2 TEMPLATE FILENAME

If you want dispatch('foo') to load something other than foo.html, call
the load_template() method.

  $self->load_template('bar');

=head2 AUTHORIZATION

It is common to have content that "anyone can see" and content that
"cannot be seen without logging in". In Sledge, you can authorize per
page by defining a factory method called create_authorizer() in each
Pages class that returns a subclass of Sledge::Authorizer.

For example, let's accept only requests that have a parameter called
foobar in the cookie. Create YourProj::Authorizer::CookieFoobar.

  package YourProj::Authorizer::CookieFoobar;
  use base qw(Sledge::Authorizer);

  use Apache::Cookie;

  sub authorize {
      my($self, $page) = @_;
      my %cookie = Apache::Cookie->fetch;
      unless ($cookie{foobar}) {
          $page->redirect('/autherr.cgi');
      }
  }

  1;

Here it is set up so that a failed authorization redirects to
/autherr.cgi. With the current interface, nothing other than issuing a
redirect here is anticipated.

Inherit from the Pages class and override create_authorizer.

  package YourProj::Pages::NeedsCookieFoobar;
  use base qw(YourProj::Pages);

  use YourProj::Authorizer::CookieFoobar;
  sub create_authorizer {
      my $self = shift;
      return YourProj::Authorizer::CookieFoobar->new($self);
  }

  sub dispatch_foo { }

  1;

Then just call this Pages from a .cgi.

   #!/usr/local/bin/perl
   use YourProj::Pages::NeedsCookieFoobar;
   YourProj::Pages::NeedsCookieFoobar->new->dispatch('foo');
